# AcademicApply 1.9.0

Discovery now starts with native provider web search and supplements it with selected, accessible connectors. Separate country, role and specialist-topic queries cover broad computing/AI faculty roles as well as speech and cognitive-health research. Country rotation prevents Europe from consuming the entire initial budget. Local academic titles and selected portal domains add coverage.

Search results first enter a durable candidate store with title, institution, excerpt, exact query and source provenance. Public page extraction, permitted JavaScript rendering and official-employer research then retrieve descriptions, eligibility, requested submission documents, deadlines and application links. Only a matching, sufficiently detailed vacancy with an identified employer enters Full listings. Unknown fields remain flagged. Independently read pages and provider-reported evidence have distinct verification status; supplemental provider facts retain field provenance. Duplicate aliases update one record while distinct same-title openings remain separate.

Discover now has Full listings and Needs detail review views. Complete pending details resumes extraction without rerunning broad queries. Individual candidates support detail research, ignore/restore, opening visible Chrome and importing its visible vacancy text after manual verification. Private form values are omitted. Browser controls use a separate serialized queue so a long background search does not block them.

Search depth controls expose real bounds: Quick 8 queries / 100 candidate links / 24 detail attempts / 10 minutes; Balanced 24 / 350 / 100 / 25 minutes; Thorough 80 / 1500 / 300 / 35 minutes. These are maximum budgets, not promised results; provider latency can exhaust time earlier. Coverage persists across one-off and saved searches. Subsequent identical runs continue uncovered queries and retained candidates; a completed query cycle starts again on the next run. Weekly schedules use the same pipeline. Limits, unresolved candidates, exclusion reasons, query outcomes, native actions and full-listing counts appear in Activity.

Settings adds Test web search for each provider, separate from authentication/drafting Test service. Codex app-server and persistent Antigravity ACP report observed completed native web actions. Provider-reported query execution is distinguished from observed actions. A subscription/model without working internet tools cannot silently be treated as a verified search service.

Extraction repairs include timezone-stable date-only parsing, explicit employer deadline wording, doctoral-thesis attachment requests, preservation of supplemental requirements, title-less JavaScript loading pages, per-search cancellation/log identity and standalone visible-page import.

Validation on 20 November 2026: 120 automated tests, a production renderer build, controlled Electron full-detail workflow with actual visible Chrome, real headless installed Chrome rendering, and native search in both Codex and Antigravity. A bounded live Codex run collected 62 candidate URLs and saved four full ads; a follow-up detail-only pass saved three additional full ads while requesting no broad queries. Many candidates remained unresolved or required review. These runs demonstrate retrieval and resumability, not exhaustive coverage or completion of every candidate. No production listing/profile data was used as provider prompt context in these public-job tests, and no real application or email was submitted.

Use Automatic page reading by default. Headless Chrome runs JavaScript efficiently on accessible public pages; visible Chrome is for manual verification and account-specific interaction. Access restrictions are reported rather than bypassed. Neither browser mode guarantees inclusion in search indexes or access to every portal. Google documents stale/expired result issues and the complete JobPosting description fields: https://developers.google.com/search/docs/appearance/structured-data/job-posting . Playwright documents installed Chrome and headless support: https://playwright.dev/docs/browsers .
